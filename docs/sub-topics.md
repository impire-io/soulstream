# Sub-topics: threads without the mess

Sometimes a topic sprouts a side-conversation that deserves its own space but still
belongs to the main one. Instead of starting a whole separate topic (and losing the
connection) or letting it clutter the main thread, you clip a **sub-topic** underneath —
like a **sticky-note thread clipped inside a page** of the notebook.

- It has its **own pages** (its own op-log), so the side-conversation stays tidy and
  separate.
- It's **still findable** under its parent on the notice board, so nobody loses track of
  it.
- You can nest as **deep as you like** — a sticky note on a sticky note — and nothing
  special has to change to allow it.

## How it works (the simple trick)

A sub-topic's address is just its parent's address with the child's name added on the
end, joined by a dot:

```
q2-vat-filing-x7m2                      (the topic)
q2-vat-filing-x7m2.pricing-angle-c2d9   (a sub-topic under it)
```

That's the entire mechanism — no new machinery. Because each topic reads only its *own*
pages, the parent doesn't get flooded with the sub-topic's chatter, and the sub-topic
catches up on its own.

## Lost parents aren't hidden

If a sub-topic points at a parent the board can't find, it's **flagged** ("parent
unknown") but still shown — better to surface a loose thread than to quietly drop it.

## When is it a sub-topic vs. a new topic?

If it's the *same job, a narrower slice* → sub-topic. If it's really a *different job*
that wandered off → start a fresh top-level topic. It's an editorial call, and it's
correctable — just say so in the topic.
